## 2026-11-02 · 性能优化（体检 + 改造）

**体检结论**
- 视频：站内无 `<video>` / mp4，不涉及。
- GSAP：项目未使用（只有 CSS 动画 + rAF），不涉及。
- 滚动监听：无 `scroll` 事件监听（用 wheel/pointer + IntersectionObserver），本来就合格。

**已修的真问题**
1. `public/images/anime-covers`：164 张原图共 **143.5MB**（最大单张 2.3MB），却只当 54px 缩略图用。全部转成 **220px 宽 WebP** → **2.85MB**（-98%），文件名改 `.webp` 并同步 `animeCovers.ts`。
   - 事故与恢复：写数据文件时正则未命中→写空，靠 Edge 磁盘缓存 `Cache_Data/f_01126d`（开发服务器返回的模块原文）找回 164 条「文件名→番剧名」映射，顺序与名字完整。
2. 字体：`zpix.ttf` **6.9MB** 且被 `preload` 卡在首屏。用 fontTools 按站内实际用到的 **3529 个字符**做子集 → **zpix.woff2 137KB**。完整字体移到 `assets/fonts-src/zpix-full.ttf`（不进构建），新增文字后需重新子集。
3. 首屏 JS：原本单 chunk **1.63MB**（gzip 591KB），且 `three` 因 ConsolePanel 静态引入被打进首屏。改为：`SectionView` / `ConsolePanel` 用 `React.lazy` + 首屏后 1.5s 预取；`vite.config.ts` 加 `manualChunks` 拆出 react / three / r3f / ogl。
   - 现在：index 64KB + react 146KB + CSS 52KB ≈ **gzip 82KB**；three(752KB)+r3f(130KB)+SectionView(534KB) 只在进分区时加载。
4. `GlitterWarp`（控制台背景）即使面板关闭也每帧渲染：加 `paused` prop，暂停时真正 `cancelAnimationFrame` 且不再 `render`，`ConsolePanel` 传 `paused={!open}`。
5. `useClock` 原本在 `App` 里，每秒 setState 导致整棵 App 树重渲染（进入分区后每秒 reconcile 一次大文档）。下沉到 `BottomHud` 内部，App 不再按时钟刷新。
6. 小说封面 5.1MB → 1.4MB（720px 宽、progressive JPEG）。

**结果**
- `public` 总量 270MB → **118.7MB**；首屏实际下载 ~7.5MB → **~220KB**。
- 剩余大目录（travel 25.5MB / ukulele 54.6MB / anime 30MB）都是按页/按曲目按需加载，未动。
